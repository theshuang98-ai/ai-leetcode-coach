# AI 产品经理面试材料 · AI LeetCode 私教

> 用法：面试前 10 分钟过一遍「30 秒开场 + 5 分钟演示脚本 + Q&A」。
> 原则：不把项目讲成「我写了个全栈应用」，而是讲成「我发现问题 → 定义 AI 场景 → 设计 Prompt/流程 → 用数据验证 → 算清商业账」。

---

## 一、30 秒开场

> 「这是一个 AI 刷题教练。目标用户是准备技术面试、但不知道每天该刷什么的人。
>
> 产品把刷题拆成一个闭环：按专题选计划 → 每天推 3–5 题 → 卡住时 AI 分层提示 → 做完评分 → 算法安排下次复习。
>
> 我刻意没让 AI 直接给答案：**规则引擎负责『刷什么』，LLM 负责『怎么讲』**。这样选题可解释、零 token，AI 只花在真正需要个性化的讲解上。」

## 二、JD 五条职责怎么对上

### 1. 场景定义与落地：0 → 1

| JD 要求 | 项目证据 | 讲法 |
|---|---|---|
| 找到有商业价值的 AI 场景 | 题库 205 题、每日推送、SM-2 复习、AI 教练 | 从「刷题三大痛点」倒推功能，不是先有模型再找场景 |
| 完成 0→1 | 10 个页面、15+ API、真实 DeepSeek 流式接入、演示数据 | 已不是 PPT，本地可完整跑通 |

**关键句**：AI 不是产品，**学习闭环才是产品**；LLM 只是闭环里的一个环节。

### 2. Prompt 设计与 Agent 编排

**System Prompt 结构（可现场打开 `app/api/coach/route.ts`）**

```
角色：LeetCode 私教
上下文：题号 + 中英文标题 + 专题 + 难度
本轮模式：hint1 / hint2 / hint3 / review / chat
教学原则：苏格拉底式、≤150 字、不直接给答案、不编造条件、先指出第一个错误
```

**分层提示（核心设计）**

| 层级 | 给什么 | 不给什么 | 目的 |
|---|---|---|---|
| L1 方向 | 考点、第一步该想什么 | 数据结构名以外的方法 | 防止一上来被剧透 |
| L2 思路 | 数据结构 + 关键步骤 | 代码 | 保留实现空间 |
| L3 边界 | 边界条件、复杂度、伪代码骨架 | 可提交代码 | 面试前自检 |
| 复盘 | 指出漏洞、面试表达建议 | 重写答案 | 练表达，不是抄答案 |

**为什么分层**：直接问答会让用户「看懂 ≠ 会做」；分层把 AI 变成教练而不是答案库，同时 L1 更短，**token 成本更低**。

**Prompt 版本化**：响应头返回 `X-Coach-Prompt-Version: coach-v1.2`，前端展示；每次改 Prompt 都可灰度、回滚、对比。

**Agent 流程（当前是混合式，不硬吹全自动）**

```
选计划（规则）
  → 选题引擎（SM-2 + 依赖锁 + 复习上限 30%）
  → 每日推送（确定性，可解释）
  → AI 教练（LLM，按 mode 生成）
  → 评分（规则）
  → 下次复习时间（规则）
  → 反馈落盘（Bad Case）
```

**为什么不让 LLM 直接选题**：成本高、延迟高、结果不稳定、无法解释「为什么今天推这题」。LLM 适合开放讲解，不适合做调度策略。

**下一步 Agent 化**：给教练加 tool calling（查用户进度、查前置题、查官方题解、写复习计划），从「单轮讲解」升级成「诊断 → 计划 → 陪练」。

### 3. 技术到商业的翻译

| 技术语言 | 产品/商业语言 |
|---|---|
| SM-2、复习上限 30% | 每天 20 分钟能完成，不会越积越多 |
| 流式输出 | 首字 0.8–1.5s，等待感可接受 |
| Prompt 分层 | 降低 token 成本，同时保护学习效果 |
| 14 天遗忘阈值 | 避免「假复习」，到期没做就重学 |
| 反馈 JSONL | Bad Case 可导出，能持续迭代模型效果 |

### 4. 数据与 Bad Case 闭环

**已经做的**

- 每条 AI 回答 👍/👎 → `POST /api/coach/feedback` → `data/coach-feedback.jsonl`
- 日志字段：用户、题目、mode、Prompt 版本、问题、回答、延迟、评分
- 前端显示首字延迟 / 总耗时，出问题能定位是模型慢还是网络慢

**下一步（面试时主动说「还没做」比被问出来好）**

1. 每周导出低分样本 → 人工归类（剧透 / 答非所问 / 幻觉 / 太长）
2. 每类对应一个 Prompt 修复，版本号 +1
3. 建 50 题离线 eval：同一批题跑新旧 Prompt，人工按「是否给答案、是否正确、是否有下一步」打分
4. 线上看 L1→L2 升级率、提示后 24h 内完成率、7 日留存

### 5. 商业化与 ROI

**定价假设**：¥99/月（已有着陆页与订阅骨架）。

**单用户 AI 成本（用公式，不背死数字）**

```
每次提示 ≈ 1,000 input tokens + 300 output tokens
每天 3 次 → 每月 90 次
成本 = 90 × (input 单价 × 1k + output 单价 × 0.3k)
```

按 DeepSeek 公开价量级估算，单用户每月 AI 成本约 **¥0.1–0.5**，相对 ¥99 订阅可忽略。
真正成本在：获客、题库维护、内容审核。

**商业化路径**

1. 免费：每日 3 题 + 每天 3 次 L1 提示
2. 订阅 ¥99/月：无限计划、L2/L3 提示、复盘、数据看板
3. 分发：Chrome 扩展（做题时自然触达）+ 校园/训练营合作
4. 北极星指标：**周完成计划题数**（不是 DAU，刷题产品看行为深度）

**ROI 判断**：AI 只在「讲解」环节用，单次成本可控；如果未来做「AI 自动出计划」，要先验证它比规则引擎的完成率高，否则不上。

## 四、高频追问 Q&A

**Q：用户为什么不用 ChatGPT / 直接看题解？**
A：ChatGPT 不知道你的 205 题计划、今天该复习哪题、哪类题薄弱；题解是「看懂」，教练是「让你做出来」。产品价值在**上下文 + 计划 + 复习节奏**，不在模型本身。

**Q：这算 AI 产品吗？核心不是 SM-2 吗？**
A：SM-2 是确定性的调度策略，AI 是交互层。没有 AI，产品是「题单 + 提醒」；有 AI，才能在卡住时给出个性化提示和复盘。两者互补，不是二选一。

**Q：怎么防止 AI 直接给答案？**
A：三层：Prompt 约束（分层、不给可提交代码）、交互约束（默认 L1，需要主动升级）、产品约束（提示按钮不叫「看答案」）。再加人工抽查低分样本。

**Q：模型幻觉怎么办？**
A：当前用标题 + 专题做上下文，明确要求「不确定就说假设」；下一步接官方题解做 RAG，答案里给引用；离线 eval 加「事实错误」维度。

**Q：为什么不做微调？**
A：现在样本量不够，微调成本和迭代速度都不划算。Prompt + 反馈闭环先跑；当某类错误稳定复现、且 Prompt 修不动时，再考虑 SFT/LoRA。

**Q：AI 成本会不会失控？**
A：L1 短、L2/L3 才长；免费额度限次数；将来可 L1 用小模型、L3 用大模型。按公式算，单用户月成本远低于订阅价，真正的成本是获客。

**Q：数据从哪来？**
A：题库与难度分来自公开题单整理（已在页脚注明灵茶题单启发）；用户数据来自做题行为与评分；AI 反馈来自点赞点踩。后续会补数据合规与用户授权。

**Q：如果只能做一个改进，做什么？**
A：把「提示 → 完成 → 复习」的漏斗打通并可视化，用数据证明 AI 提示提升了完成率和 7 日留存；没有这个证据，功能再多都是自嗨。
